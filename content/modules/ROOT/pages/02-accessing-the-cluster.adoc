= Accessing the Cluster
:navtitle: Accessing the Cluster
:imagesdir: ../images

All RAG components run inside your OpenShift project (Kubernetes namespace) for this lab.
Your namespace is `{user}-rag`.
This page walks through what you should see for pods, services, and routes, and how to reach the chatbot user interface (UI).

== Accessing the cluster

. Click the *OpenShift Console* button in the top right of the demo platform to open the OpenShift web console.
+
image::openshift-click.png[OpenShift UI,role=expand]

. Log in with the credentials below.
+
Username::
+
[source,text,subs=attributes+]
----
{user}
----
+
Password::
+
[source,text,subs=attributes+]
----
{password}
----

== Checking pods

. You will see a single project in the OpenShift UI. In the top left hand corner click on the hamburger menu and select *Workloads → Pods*.
+
image::pods.png[Pods,role=expand]
+
[IMPORTANT]
====
If the Pods page shows *Restricted access — You don't have access to this section due to cluster policy* with an error like `pods is forbidden: User "{user}" cannot list resource "pods" in API group "" at the cluster scope`, the console is trying to list pods across *all* projects, which your lab user is not allowed to do.

Click the *Project: All Projects* dropdown at the top of the page and select your project, *{user}-rag*. The pod list appears once a single project is selected.

image::restricted-access-select-project.png[Selecting your project from the Project dropdown to resolve the Restricted access error,role=expand]
====

. Confirm the pods below are `Running` or `Completed`.

.Key pods to verify
[cols="2,3",options="header"]
|===
|Pod label (`app.kubernetes.io/name=`) |Purpose

|`rag`
|The RAG UI (chatbot web interface) served to the user

|`llamastack`
|LlamaStack server: orchestrates the LLM, embeddings, and tools

|`pgvector`
|PostgreSQL + pgvector extension: stores document embeddings for the vector store

|`ingestion-pipeline`
|REST API that receives document-ingestion requests and hands them off to the Data Science Pipelines Application

|`minio`
|S3-compatible object storage backing the ingestion pipeline
|===

[NOTE]
====
There is no local model-serving pod in this namespace. The LLM runs on an external OpenShift AI Model-as-a-Service (MaaS) endpoint, so the `llamastack` pod only needs to reach `Running` on its own.

You will also see several `Running` pods labeled `component=data-science-pipelines` (the Kubeflow pipeline control plane) and, briefly at first boot, one `add-<department>-pipeline-pipeline` Job per pre-loaded document category. See xref:07-kubeflow-pipeline.adoc[Kubeflow Pipeline] for what these do.
====

=== Using the CLI to check pods

. Click the *Terminal* tab in the right pane to open a terminal, then log in to the cluster:
+
[source,bash,role="execute",subs=attributes+]
----
oc login --insecure-skip-tls-verify \
  -u {user} \
  -p {password} \
  {openshift_api_url}
----
+
_Expected output:_
+
----
Login successful.

You have one project on this server: "{user}-rag"

Using project "{user}-rag".
----

. Check the pods:

oc get pods -n {user}-rag

Services expose each component internally within the cluster.

. In the OpenShift UI, click on the "Networking/Services" menu item in the left hand navigation.
+
image::services.png[Services,role=expand]

. Or run the following command from the CLI:
+
[source,bash,role="execute",subs=attributes+]
----
oc get svc -n {user}-rag
----
+
_Expected output (trimmed):_
+
----
NAME                     TYPE        CLUSTER-IP       EXTERNAL-IP   PORT(S)                      AGE
rag                      ClusterIP   172.30.45.12     <none>        8501/TCP                     5m
ingestion-pipeline       ClusterIP   172.30.73.195    <none>        80/TCP                       5m
llamastack               ClusterIP   172.30.61.254    <none>        8321/TCP                     5m

.What each service does
[cols="2,3",options="header"]
|===
|Service |Purpose

|`rag`
|Internal endpoint for the RAG UI (the chatbot web interface, port 8501); exposed to your browser through the `rag` route

|`ingestion-pipeline`
|Internal REST API that receives document-ingestion requests (port 80)

|`llamastack`
|Internal REST API for the LlamaStack server (port 8321)

|`pgvector`
|Internal PostgreSQL + pgvector endpoint (port 5432)

|`minio`
|Internal S3-compatible object storage used by the ingestion pipeline

|`ds-pipeline-dspa` and related `ds-pipeline-*`/`mariadb-dspa` services
|Kubeflow Data Science Pipelines Application control plane that executes ingestion pipeline runs
|===

== Checking routes

Routes expose the UI and API to the outside world.

. In the OpenShift UI, click on the "Networking/Routes" menu item in the left hand navigation.
+
image::routes.png[Routes,role=expand]

. Or run the following command from the CLI:
+
[source,bash,role="execute",subs=attributes+]
----
oc get routes -n {user}-rag
----
+
_Expected output (trimmed):_
+
----
NAME                  HOST/PORT                                                           PATH   SERVICES                          PORT    TERMINATION          WILDCARD
rag                   rag-{user}-rag.{openshift_cluster_ingress_domain}                          rag                               8501    edge/Redirect        None
ds-pipeline-dspa      ds-pipeline-dspa-{user}-rag.{openshift_cluster_ingress_domain}             ds-pipeline-dspa                  proxy   reencrypt/Redirect   None
ds-pipeline-md-dspa   ds-pipeline-md-dspa-{user}-rag.{openshift_cluster_ingress_domain}          ds-pipeline-metadata-envoy-dspa   proxy   reencrypt/Redirect   None
minio-api             minio-api-{user}-rag.{openshift_cluster_ingress_domain}                    minio                             api     edge/Redirect        None
minio-webui           minio-webui-{user}-rag.{openshift_cluster_ingress_domain}                  minio                             webui   edge/Redirect        None
----

. The `rag` route is the one that serves the chatbot. To filter directly to it by label:
+
[source,bash,role="execute",subs=attributes+]
----
oc get routes -l app.kubernetes.io/name=rag -n {user}-rag
----
+
_Expected output:_
+
----
NAME   HOST/PORT                                            PATH   SERVICES   PORT   TERMINATION     WILDCARD
rag    rag-{user}-rag.{openshift_cluster_ingress_domain}           rag        8501   edge/Redirect   None
----

The `HOST/PORT` value is assigned by your cluster. Copy the exact URL from your own `oc get routes` output.

.Route breakdown
[cols="2,3",options="header"]
|===
|Route |Purpose

|`rag`
|*This is the URL that serves the chatbot (the RAG UI).* The *RAG UI* tab in the right pane opens this same route, so you normally don't need to copy the URL by hand.

|`ds-pipeline-dspa` / `ds-pipeline-md-dspa`
|Internal API access to the Kubeflow Data Science Pipelines Application; not needed for the chat workflow.

|`minio-webui` / `minio-api`
|Console and API access to the object storage backing the ingestion pipeline; useful for inspecting uploaded documents.
|===

The LlamaStack API itself has no route: it is only reachable from inside the cluster.

== What to expect in the UI

Click the *RAG UI* tab in the right pane to open the chatbot. It is served by the `rag` route you just found, so you don't need to copy the URL by hand — but you can also open that route's `HOST/PORT` value in a browser tab directly.

When the RAG UI loads you will see:

* A chat input box at the bottom of the screen for submitting questions
* A left sidebar with configuration options:
** *Model*: the LLM currently serving responses
** *Processing mode*: toggle between *Direct* (simple RAG) and *Agent-based* (agentic RAG with tool calling)
** *Select Document Collections for RAG queries*: appears once at least one knowledge base exists; choose which vector store collection to query
** *Sampling parameters*: adjust temperature, top K, max tokens, and (in Agent-based mode) max inference iterations
** *System prompt*: override the default system prompt

The application comes pre-loaded with FantaCo's internal HR, Legal, Procurement, Sales, and TechSupport documents so you can begin asking questions immediately.
