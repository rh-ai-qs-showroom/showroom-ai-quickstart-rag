= Creating a Knowledge Base and Adding Documents
:navtitle: Knowledge Base
:imagesdir: ../images

The RAG pipeline uses PostgreSQL with the PGVector extension as its vector store. New knowledge bases (collections) and document ingestion are managed through the UI or through Kubeflow Pipelines.

== Creating a new knowledge base via the UI

. Click the *RAG UI* tab in the right pane to open the chatbot, then click *Upload Documents* in the left sidebar.
+
image::rag-ui-chat.png[The RAG UI Chat playground,role=expand]
. From the *Select a vector database* dropdown, choose *➕ Create New* (already selected by default if you have no knowledge bases yet).
+
image::create-new-dropdown.png[Create New Vector Database form,role=expand]
. Enter a unique name in the *Add New Vector Database* field (e.g., `my-kb`) and click *Add*.
+
image::create-vector-db.png[Naming the new vector database,role=expand]
. Confirm creation. A success message appears, the new collection is registered in PGVector, and the *Select a vector database* dropdown switches to it automatically.

== Adding documents via the UI

. With your collection selected, choose an *Extraction method*:
.. *LlamaStack Provider*: for `.txt`, `.pdf`, and `.md` files (200MB per file).
.. *Docling*: for `.docx` and `.xlsx` files.
. Click *Upload* and choose one or more files from your local machine. Files upload automatically once selected.
+
[TIP]
====
Ingestion runs while you wait: each file is cleaned, chunked, and embedded before the success message appears, so this can take a few moments — larger files take longer. For a quick first run, keep uploads small (around 1 MB or less). A one- or two-page PDF embeds in a few seconds, whereas a large document can take several minutes.
====
. The UI passes each file through the ingestion pipeline which:
.. Cleans and chunks the document text
.. Generates embeddings using the configured embedding model
.. Stores the embedding vectors in PGVector under your chosen collection
. When ingestion finishes, a green *Successfully uploaded* banner confirms the document is in your collection, and the file appears in the *Documents in '<collection>'* list above.
+
image::upload-success.png[Successful document upload confirmation showing the green success banner,role=expand]

== Extraction and chunking mode

Document extraction and chunking can run in one of two modes:

* *Local*: extraction and chunking happen directly inside the application. This is the default mode and requires no additional infrastructure.
* *Pipeline*: extraction and chunking are offloaded to a Kubeflow Pipeline running on OpenShift AI. This is better suited for large-scale or batch ingestion workloads. See xref:07-kubeflow-pipeline.adoc[Kubeflow Pipeline] for configuration details.

[NOTE]
====
A toggle to switch between local and pipeline-based extraction/chunking is being added and will be available in an upcoming release.
====
