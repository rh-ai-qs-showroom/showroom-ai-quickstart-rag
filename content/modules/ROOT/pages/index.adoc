Use retrieval-augmented generation (RAG) to enhance large language models with specialized data sources for more accurate and context-aware responses.

== About this QuickStart

See how FantaCo, a fictional large enterprise, launched a secure RAG chatbot that connects employees to internal HR, Legal, Procurement, Sales, and TechSupport documentation.

From policies to startup guides, employees get fast, accurate answers through a single chat interface.
Advanced users can extend the experience with AI agents for deeper workflows.

Retrieval-Augmented Generation (RAG) enhances Large Language Models (LLMs) by retrieving relevant external knowledge to improve accuracy, reduce hallucinations, and support domain-specific conversations.

== What you can do

The application comes pre-loaded with FantaCo's internal documents so you can begin exploring immediately.
Use the sidebar on the left to configure the experience:

=== Switch between processing modes

* *Direct*: simple, single-turn RAG. Passes vector store search results as context straight to the LLM. Select a knowledge base, ask a question, and get a grounded answer with source citations. See xref:04-chat-mode.adoc[Chat Mode].
* *Agent-based*: multi-step, agentic RAG using the Responses API with tool calling. The LLM plans, reasons, and calls tools (e.g., knowledge base retrieval, web search) across multiple turns before returning a final answer. See xref:05-agent-mode.adoc[Agent Mode].

=== Tune model parameters

The sidebar exposes several sampling controls that influence how the LLM generates responses:

[cols="1,3",options="header"]
|===
|Parameter |What It Does

|*Temperature*
|Controls randomness. Lower values (e.g., 0.1) produce more deterministic, focused answers. Higher values (e.g., 0.9) increase creativity and variation.

|*Top K*
|Restricts the model to sampling from only the _k_ most likely next tokens. Lower values reduce randomness; higher values allow more diversity.

|*Max Tokens*
|Caps the length of the generated response. When RAG retrieval is active, set this high because retrieved chunks consume a significant portion of the token budget.

|*Max Inference Iterations*
|Agent-based mode only. Caps how many tool-calling/reasoning loops the agent can run before it must return a final answer.

|*System Prompt*
|Override the assistant's persona or add constraints (e.g., "Answer only in bullet points." or "Respond in Spanish.").
|===

=== Work with knowledge bases

* Browse, create, and select knowledge base collections backed by PostgreSQL + PGVector.
* Upload your own documents to create a custom knowledge base: plain text, PDF, and Markdown are supported directly; `.docx` and `.xlsx` are supported via the Docling extraction method. See xref:03-knowledge-base.adoc[Bring Your Own Documents].

=== Use agent tools

When running in Agent-based mode, the LLM can call tools to extend its capabilities beyond its training data:

* *Knowledge Base Retrieval*: semantic search over your uploaded documents.
* *Web Search*: query the internet for up-to-date information the model was not trained on.

See xref:05-agent-mode.adoc[Agent Mode] for a walkthrough that demonstrates how tools appear in the chat window.

|Streamlit

|`nomic-ai/nomic-embed-text-v1.5`
|Converts text to vector embeddings

|Vector DB
|PostgreSQL + PGVector
|Stores embeddings and enables semantic search

|Retrieval
|Vector Search
|Retrieves relevant documents based on query similarity

|Data Ingestion
|Kubeflow Pipelines
|Multi-modal data ingestion with preprocessing pipelines for cleaning, chunking, and embedding generation

|Storage
|S3 Bucket
|Document source for enterprise content
